# OKX 虛擬貨幣短線監控 × Codex／Telegram

這是一個只通報、不自動下單的短線監控服務。預設監控 OKX 的 BTC、ETH、SOL USDT 永續合約，僅使用 15 分鐘已確認收盤 K 線計算分數；總分達到門檻、必要條件成立、資料完整且通過逐根確認後，預設直接輸出至 Codex／終端。若另外設定 Telegram 憑證，也可改由 Telegram 接收。

## 訊號規則

普通訊號只能輸出 `+1 / 0 / -1`：

| 群組 | 訊號 | 利多 | 利空 | 中性 |
|---|---|---|---|---|
| 趨勢 | EMA 短線方向 | 快線高於慢線且差距達門檻 | 快線低於慢線且差距達門檻 | 差距不足 |
| 動能 | MACD 柱 | 正值且擴大 | 負值且向下擴大 | 方向不一致或動能縮減 |
| 動能 | MACD 標準背離 | 已確認底背離 | 已確認頂背離 | 未確認、不完整或過期 |
| 資金流 | 現貨 CVD | 比率達正門檻 | 比率達負門檻 | 未達門檻 |
| 資金流 | 合約 CVD | 比率達正門檻 | 比率達負門檻 | 未達門檻 |
| 資金流 | CVD 分歧與價格反應 | 現貨偏多、合約偏空且價格不跌 | 現貨偏空、合約偏多且價格不漲 | 價格未確認 |
| 參與度 | 價格 × OI | 價漲且同區間 OI 增 | 價跌且同區間 OI 增 | OI 下降或未達門檻 |
| 參與度 | 相對成交量 | 放量上漲 | 放量下跌 | 未放量 |

MACD 動能與背離合計最多 `±1`；三項 CVD 合計最多 `±2`。因此基礎分數範圍為 `-6` 到 `+6`。

資金費率不提供反方向加分，只做擁擠扣分：

- 基礎分數偏多且正資金費率過高：總分減 1。
- 基礎分數偏空且負資金費率過低：總分加 1，讓空方分數靠近 0。
- 其他組合不調整分數。

## MACD 標準背離

只偵測 Regular Divergence，不包含 Hidden Divergence。

- high 用於找頂部價格樞紐，low 用於找底部價格樞紐。
- 預設左側 3 根、右側 2 根；右側 K 線收盤前不會確認樞紐。
- 兩個樞紐預設相隔 5–40 根。
- 價格差至少為第二樞紐 ATR 的 0.1 倍。
- 底背離要求第二低點價格更低、MACD 線與柱體更高。
- 頂背離要求第二高點價格更高、MACD 線與柱體更低。
- 確認後預設有效 3 根已收 K 線。
- 同一組樞紐使用穩定識別鍵防止重複通知；同時衝突且無法分先後時記 0。

通知會列出兩個價格樞紐、兩個 MACD 值及剩餘有效根數。

## 門檻與必要條件

- `>= +4`：多單；`>= +5`：強多單。
- `<= -4`：空單；`<= -5`：強空單。
- `-3` 到 `+3`：只記錄，不推播。

達到分數後仍須全部通過：

1. 方向：EMA 或已確認的同方向 MACD 背離。
2. 資金：現貨 CVD、合約 CVD、CVD 分歧或價格 × OI 至少一項同方向。
3. 群組：趨勢、動能、資金流、參與度至少三組同方向。
4. 品質：已收 K、完整 CVD 視窗、相鄰 15 分鐘 OI 樣本與 API 資料皆有效。

連續確認以不同的已收 K 線計算；同一根 K 線重掃不會增加確認次數。相同幣種與方向有冷卻時間，方向及分數未改善不重複通知；普通訊號升級為強訊號可額外通知一次。

## 停損、止盈與成本

- 一般停損使用 ATR 倍數。
- 背離訊號可使用第二樞紐加 ATR 緩衝作為較寬的停損候選。
- 只產生一個止盈，預設價格距離盈虧比固定為 1:1。
- 另外用單邊手續費與滑價假設估算成本後盈虧比。
- 停損方向錯誤、距離超限或成本後盈虧比低於設定值時，只記錄、不推播。

## CVD 與時間一致性

成交資料使用 OKX `trades-all` business WebSocket：

- 現貨與永續合約分開訂閱與計算。
- 使用 `tradeId` 去重，依 taker side 計算標準化主動買賣差比率。
- WebSocket 自動指數退避重連。
- 斷線時立即清空就緒狀態；重連後須重新累積完整視窗。
- CVD 只讀取對應已收 K 線結束時間的視窗，不直接比較現貨與合約原始數量。

官方資料：[OKX API v5](https://www.okx.com/docs-v5/en/) 與 [Telegram Bot API](https://core.telegram.org/bots/api)。

## 訊號紀錄

預設寫入 `data/signal_history.sqlite3`，保存：

- 時間、幣種、週期、價格、總分與基礎分數。
- 每個投票與群組分數。
- 背離類型、價格／MACD 樞紐、確認與失效時間。
- 四項必要條件、Telegram 是否發送及未發送原因。
- 進場、停損、單一止盈、手續費與滑價假設。
- 訊號後 1、4、8、16 根報酬，以及 16 根期間 MFE／MAE。

未來報酬會在後續 K 線出現後回填；新啟動的資料庫需要時間累積。

## BTC／ETH／SOL 四小時報告

`crypto-monitor-report` 讀取監控服務已寫入的 SQLite 最新 15 分鐘資料，整理 BTC、ETH、SOL 的：

- 分數、目前多空狀態與資料完整度。
- 現貨／合約 CVD、OI 變化、資金費率。
- 相對成交量、MACD 與最近一次通報結果。

有 Telegram 憑證時會送到 Telegram；否則直接輸出到 Codex／終端。此報告不下單，也不會改動策略設定。第一次啟動監控、或 CVD／OI 尚在暖機時，報告會明確標示資料尚未完整。

本機可手動執行：

```bash
crypto-monitor-report
```

## 設定

專案已包含 `config.yaml`，公開 OKX 行情不需要 API Key，也不需要 `.env`。直接啟動即可使用 Codex／終端輸出。

Telegram 是可選功能。只有需要 Telegram 通知時才建立 `.env`：

```dotenv
TELEGRAM_BOT_TOKEN=你的_token
TELEGRAM_CHAT_ID=你的_chat_id
CONFIG_PATH=config.yaml
```

Token 等同密碼，不要提交至版本控制或貼在聊天中。兩個 Telegram 欄位任一未設定時，程式會自動使用 Codex／終端輸出。策略參數、背離樞紐、CVD、OI、相對成交量、資金費率、冷卻、ATR、1:1 盈虧比及成本假設都在 `config.yaml`。

## 啟動

Docker：

```bash
docker compose up -d --build
docker compose logs -f
```

Docker 不再強制要求 `.env`；若要啟用 Telegram，可自行提供環境變數。

本機 Python 3.11 以上：

```bash
python -m venv .venv
pip install -e ".[dev]"
crypto-monitor
```

啟動後需要持續運行：CVD 必須先累積完整 15 分鐘視窗，OI 也至少需要相鄰兩根已收 K 線樣本。在暖機完成前只記錄資料，不會產生交易通報。

### 在 Codex 直接判斷

在這個專案中要求 Codex 啟動或檢查監控即可；沒有 Telegram 時，符合條件的多單／空單會直接出現在終端輸出並寫入 SQLite。若使用 Codex Scheduled task，電腦與 Codex App 在需要本機專案資料時必須保持開啟。

Windows PowerShell 啟用環境：

```powershell
.venv\Scripts\Activate.ps1
```

## 已知限制

- OKX 公開 OI 是掃描當下快照；程式只在新已收 K 線出現時保存快照，以下一根收盤快照計算近似的 15 分鐘 OI 變化。服務剛啟動時缺少上一根樣本，因此不會立即推播。
- `trades-all` 沒有提供可補回斷線期間成交的機制；程式採保守策略，斷線後整個 CVD 視窗重新暖機。
- 門檻 `±4` 與 1:1 是固定的第一版基準，尚未證明具有統計優勢；正式使用前應累積紀錄並做走勢外驗證。

⚠️ 本程式輸出為條件式短線通報，不保證獲利，也不構成投資建議。
